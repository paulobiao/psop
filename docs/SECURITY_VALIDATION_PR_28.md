## Purpose

This report records the security validation performed for the authentication controls introduced by PR #28.

The implemented controls protect access to PSOP, a platform designed to monitor heterogeneous physical-security and cyber-physical devices.

## Security capabilities validated

The validation covered:

- mandatory replacement of temporary passwords;
- short-lived authentication challenges;
- single-use password-change challenges;
- TOTP authentication compatible with authenticator applications;
- encrypted storage of TOTP secrets;
- one-time recovery codes;
- keyed hashing of recovery codes;
- recovery-code consumption and replay prevention;
- regeneration of recovery codes;
- secure MFA deactivation;
- session creation only after all required authentication stages;
- audit logging of security-sensitive actions;
- redaction of passwords, secrets and authentication codes.

## Security design observations

### Temporary-password protection

New users cannot establish an authenticated session until the temporary password has been replaced. The replacement challenge is short-lived and single-use.

### TOTP secret protection

Authenticator secrets are encrypted using AES-256-GCM before storage. The encryption key is supplied through environment configuration and is not committed to the repository.

### Recovery-code protection

Plain recovery codes are returned only when initially generated or regenerated. Stored values use keyed hashes rather than reversible plaintext.

### Replay resistance

Completed password-change challenges and MFA challenges cannot be reused. Consumed recovery codes are removed from the active recovery-code set.

### Audit protection

Sensitive fields, including passwords, tokens, TOTP codes, secrets and recovery codes, are excluded or redacted from audit metadata.

## Post-validation automation update

Following the original PR #28 validation, permanent Jest unit tests were added for the cryptographic MFA service.

The automated suite covers:

- Base32 TOTP secret generation;
- RFC 6238 compatible TOTP verification;
- previous, current and following time-window validation;
- rejection of codes outside the permitted window;
- AES-256-GCM encryption and decryption;
- rejection of altered authentication tags and ciphertext;
- encryption-key length validation;
- recovery-code format and uniqueness;
- keyed recovery-code hashing;
- normalized recovery-code comparison;
- rejection of incorrect recovery codes.

These tests are executed automatically by PSOP CI on pull requests and pushes to `main`.
